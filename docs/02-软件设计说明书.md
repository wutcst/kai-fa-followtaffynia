# World of Zuul 拓展项目 — 软件设计说明书（SDD）

**文档版本**：2.2  
**对应需求文档**：`01-需求规格说明书.md` v2.1  
**架构风格**：分层 + Engine API + LibGDX 像素客户端（GUI 唯一入口）  
**文档日期**：2026-05-26  

---

## 1. 设计目标

1. **GUI 唯一入口**：`RpgMain` 为交付主程序；不维护 CLI 循环。  
2. **逻辑与表现分离**：`GameEngine` 不依赖 LibGDX；`GameScreen` 只调用 Engine 公开 API。  
3. **像素 RPG 体验**：Tiled + 精灵动画 + 互动提示 + Scene2D UI。  
4. **数据驱动世界**：Factory + Tiled 对象层 + 对话 JSON。  
5. **可存档**：仅序列化 `GameState` 动态字段。

## 3. 逻辑架构（四层）

| 层 | 职责 | 包路径 | 主要类 |
|----|------|--------|--------|
| **Client** | 渲染、输入、UI | `...zuul.client` | `RpgMain`, `GameScreen`, `Hud`, `DialogueBox` |
| **Application** | 游戏规则与流程 | `...zuul.engine` | `GameEngine`, `CombatEngine`, `QuestManager`, `EndingEvaluator` |
| **Domain** | 实体 | `...zuul.domain` | `Room`, `Item`, `Player`, `Npc`, `Interactable` |
| **Infrastructure** | 世界、存档、资源 | `...zuul.infra` | `WorldFactory`, `SaveGameService`, `AssetCatalog` |

### 3.1 依赖规则

```
client  ──► engine ──► domain
engine  ──► infra  ──► domain
client  ──X──► domain   （禁止 UI 直接改 Room 状态）
```

### 3.2 关于原 Command / Parser

原 Zuul 的 `Command`、`Parser` **不对外暴露**。`GameEngine` 内部可用私有 `*Handler` 组织逻辑（原 Command 类可逐步迁入），但 **GUI 只认 Engine 方法**，不使用 `GameCommand` 字符串分发。

### 5.2 GameEngine API（冻结见 `04` §10）

```java
public final class GameEngine {
    public boolean movePlayer(Direction direction);
    public boolean takeItem(String itemId);
    public boolean dropItem(String itemId);
    public void dropAllItems();
    public boolean useItem(String itemId);
    public void eatItem(String itemId);      // magic cookie → maxWeight += 20
    public Dialogue talkNpc(String npcId);
    public String look();
    public boolean moveBack();
    public GameState captureState();
    public void restoreState(GameState state);
}
```

- 返回 `boolean` 表示成败；GUI 用浮动文字提示失败原因（超重、门锁定等）。  
- 复杂结果（对话）返回 `Dialogue` 对象给 `DialogueBox`。

## 7. Tiled 与内容工作流（成员 A）

目录结构与风格见 `05-美术资源设计说明书.md`；技术参数见 `04` §2、§7。推荐 **一 Room 一 tmx**。

### 7.1 多入口 spawn

- spawn 对象属性 `direction=north|south|east|west|default`  
- 从北侧进入本房 → 使用 `direction=south` 的 spawn（玩家在房间南侧出现）  
- 无匹配时用 `default`

### 7.2 传送房间（统一规则）

**规则（全文统一）**：

1. 玩家经 `movePlayer` **已成功进入**房间 `R`，且 `R.isTeleport() == true`；  
2. **在同一调用内**，Engine 立即执行 `currentRoom = WorldFactory.randomRoomExcept(R.roomId)`；  
3. `entryDirection` 置为 `default`，玩家落在目标房 `default` spawn；  
4. 向 GUI 发送 `GameEvent.TELEPORTED`（闪白特效 + 加载新地图）。

```java
private void resolveTeleportIfNeeded() {
    if (!currentRoom.isTeleport()) return;
    String fromId = currentRoom.getRoomId();
    currentRoom = WorldFactory.randomRoomExcept(fromId);
    entryDirection = Direction.DEFAULT;
    // roomHistory 仍记录进入传送房之前的历史，便于 back
}
```

**注意**：传送房**没有**「再选出口」步骤；进入即触发。仅 `teleport-alcove`（可扩展同类房间）设置 `isTeleport=true`。

### 7.3 对话 JSON

`assets/dialogue/<npcId>.json`，格式见 `04` §6。`talkNpc` 加载并返回 `Dialogue`。

### 7.4 精灵表

见 `04` §7（玩家 4×4 帧，32×32）。

## 8. GameEngine 核心逻辑

### 8.1 movePlayer

```java
public boolean movePlayer(Direction direction) {
    Room next = currentRoom.getExit(direction.name().toLowerCase());
    if (next == null) return false;
    if (!isPassable(next, direction)) return false; // 锁门等

    roomHistory.push(currentRoom.getRoomId());
    entryDirection = direction;
    currentRoom = next;
    resolveTeleportIfNeeded();
    questManager.onRoomEntered(currentRoom);
    return true;
}
```

### 8.2 takeItem / 负重

超重则放回房间并返回 `false`（见 `04` §8）。

### 8.3 moveBack（高级 back）

```java
public boolean moveBack() {
    if (roomHistory.isEmpty()) return false;
    String prevId = roomHistory.pop();
    Direction reverse = entryDirection.opposite();
    currentRoom = WorldFactory.getRoom(prevId);
    entryDirection = reverse;
    return true;
}
```

**GUI 责任**：`moveBack` 成功后，根据 `entryDirection` 调用 `RoomScene.resolveSpawn(entryDirection)`，**将 PlayerSprite 设到对应格子中心**，避免回退后坐标留在墙里。

### 8.4 use / eat / Quest / Ending

`UseEffect` 策略；`QuestManager` 监听房间/物品/NPC 事件；`EndingEvaluator` 三结局（见 §17.3）。

### 8.5 NPC 遭遇与战斗（v2.2 扩展，见 §18）

靠近 NPC 时 GUI 调用 `startNpcEncounter`；选「杀害」进入 `CombatEngine` 回合循环。战斗结果写入 `GameState.defeatedNpcs`，并影响 `EndingEvaluator`。

## 17. NPC 角色设计（3 人，结局导向）

> **数据**：`assets/dialogue/<npcId>.json`（A 维护）  
> **地图**：TMX `objects` 层 `type=npc`，属性 `npcId`（A 放置）  
> **逻辑**：遭遇三选一、对话、战斗（B）；UI（C）

### 17.1 总览

| npcId | 名称 | 所在房间 | 类型 | 可否战斗 |
|-------|------|----------|------|----------|
| `guard` | 王座守卫 | `guard-room` | **关键** | 是 |
| `hermit` | 守秘隐士 | `hidden-shrine` | **关键** | 是 |
| `merchant` | 铁匠商人 | `forge` | **次要** | 否（仅对话/商店占位） |

**原则**：结局分支由 **2 个关键 NPC**（guard、hermit）的「交流 vs 杀害」驱动；merchant 丰富世界，不锁主结局。

### 17.2 各 NPC 详情

#### guard（王座守卫）— 关键

| 项 | 内容 |
|----|------|
| **叙事** | 把守 `guard-room` → `throne-hall` 的最后一个关卡 |
| **交流** | `talkNpc("guard")` → 友好选项 → `unlock:guard-gate` |
| **杀害** | 进入战斗；胜利后 `defeatedNpcs` 加入 `guard`，`guard-gate` 视同已破或走「血路」 |
| **战斗状态** | `normal`（刺击/格挡）→ `enraged`（HP≤60% 重击）→ `desperate`（HP≤20% 全力） |
| **对结局** | 杀害 → 声望 -15，**暗影权重 +**；友好交流 → 正常解锁，倾向光明/中立 |

#### hermit（守秘隐士）— 关键

| 项 | 内容 |
|----|------|
| **叙事** | 提示 gem-light 与 Realm 命运；`hidden-shrine` 内 |
| **交流** | 选「秘密」→ `reputation:+5`，任务线索更新 |
| **杀害** | 战斗较难（偏魔法/闪避技能）；胜利后失去声望加成与部分提示 |
| **战斗状态** | `calm`（护盾/治疗）→ `warned`（玩家先选敌对对话后变 `aggressive`） |
| **对结局** | 杀害 → **几乎锁暗影**（无 gem 线索 + 声望惩罚）；交流 → 光明/中立 |

#### merchant（铁匠商人）— 次要

| 项 | 内容 |
|----|------|
| **叙事** | `forge` 内交易、武器 lore |
| **交流** | `open:shop`（占位，C 可选做简易交易 UI） |
| **杀害** | **不提供**（遭遇菜单无「杀害」，或选后提示「无法对手无防备的匠人下手」） |
| **对结局** | 仅对话；不影响三结局主公式 |

### 17.3 三结局判定（扩展公式，B 实现）

在现有 `EndingEvaluator` 基础上增加 **NPC 命运** 与 **杀戮计数**：

| 结局 | 条件（优先级从高到低） |
|------|------------------------|
| **光明 LIGHT** | 背包含 `gem-light` **且** 声望 ≥ 0 **且** `guard`、`hermit` 均未被杀害 |
| **暗影 SHADOW** | 声望 < 0 **或** 杀害了 `hermit` **或**（杀害 `guard` 且无 `gem-light`） |
| **中立 NEUTRAL** | 其余（如无 gem、未极端杀戮、混合选择） |

`GameState.defeatedNpcs`：`Set<String>`，存已击败/杀害的 `npcId`。

## 18. 回合制战斗系统（优化版 MVP）

> **非实时 Black Souls**；采用 **菜单回合制 + 物品策略 + NPC 状态技能**，Engine 可单测，C 做战斗 UI。

### 18.1 设计目标

1. 与探索共用 **同一背包与 HP**，物品在战斗中有独立 `combat:` 效果。  
2. **数据驱动**：`assets/combat/<npcId>.json`，与 dialogue 并列。  
3. **不阻塞**对话线：先 `Encounter` 三选一，再分支。  
4. **阶段交付**：MVP 只实现 **guard** 完整战斗；hermit 为 P1 扩展。

### 18.2 遭遇流程（Encounter）

```mermaid
sequenceDiagram
    participant GS as GameScreen
    participant GE as GameEngine
    participant CE as CombatEngine

    GS->>GE: startNpcEncounter(npcId)
    GE-->>GS: EncounterMenu(TALK, FIGHT, LEAVE)
    alt 交流
        GS->>GE: talkNpc(npcId)
    else 杀害
        GS->>GE: startCombat(npcId)
        GE->>CE: init(combatJson)
        loop 回合
            GS->>GE: combatAction(action)
            CE-->>GS: CombatSnapshot
        end
    else 离开
        GS->>GE: leaveEncounter()
    end
```

### 18.3 玩家回合选项

| 动作 | Engine 枚举 | 说明 |
|------|-------------|------|
| 攻击 | `ATTACK` | 基础伤害 + 装备加成（`sword-rusty` +5） |
| 防御 | `DEFEND` | 本回合受伤 ×0.5 |
| 使用物品 | `USE_ITEM` | 参数 `itemId`；仅允许带 `combat:` 效果的物品 |
| 逃跑 | `FLEE` | 70% 成功；失败则本回合仍挨揍 |

### 18.4 NPC 状态与技能（JSON 驱动）

每个 NPC 含 `states` 映射；每状态有 `skills` 列表（权重随机或按 HP 阈值切换 state）。

**guard 示例技能**：

| 技能 id | 伤害 | 说明 |
|---------|------|------|
| `stab` | 8 | 普通刺击 |
| `block` | 0 | 下回合 NPC 受伤减半 |
| `heavy_slash` | 18 | 仅 `enraged` 状态 |

### 18.5 战斗用物品（扩展现有 Item.effect）

| itemId | combat 效果 |
|--------|-------------|
| `healing-herb` | `combat:heal:20` |
| `shield-wooden` | `combat:buff:defense:2`（2 回合减伤） |
| `torch` | `combat:debuff:blind:1`（guard 命中 -30%） |
| `sword-rusty` | 被动：装备时 ATTACK +5（非消耗） |

实现：`CombatActionRegistry`，模式同 `UseEffectRegistry`。

### 18.6 CombatEngine API（草案，B 实现）

```java
// 由 GameEngine 委托或内嵌
EncounterMenu GameEngine.startNpcEncounter(String npcId);
void GameEngine.leaveEncounter();

CombatSnapshot GameEngine.startCombat(String npcId);
CombatSnapshot GameEngine.combatAction(CombatAction action, String itemIdOrNull);
boolean GameEngine.isInCombat();
CombatResult GameEngine.getLastCombatResult(); // VICTORY, DEFEAT, FLED
```

**CombatSnapshot**（返回给 C 渲染）：`playerHp`, `npcHp`, `npcMaxHp`, `npcState`, `logLines`, `availableActions`, `usableItems`。

### 18.7 战斗 JSON 路径与样例

路径：`assets/combat/<npcId>.json`


### 18.8 胜负与 GameOver

| 结果 | 行为 |
|------|------|
| 玩家 HP≤0 | `GameEngine` 标记死亡 → C 显示 `GameOverScreen` |
| 胜利 | 应用 `onDefeat`（声望、解锁、defeatedNpcs）→ 更新 EndingEvaluator 权重 |
| 逃跑成功 | 无击杀标记，NPC 仍在地图上 |
